# LeLab collection integration — 2026-10-14

The operator requested LeLab for repeated demonstrations with resets. The project now launches official LeLab at a pinned commit from a separately locked Apple Silicon environment, while retaining the existing LeRobot 0.6.1 CLI environment. See [setup](../docs/SETUP.md) and [recording controls](../docs/RECORDING.md).

The launcher preloads the configured arms, original calibration paths, and both cameras. It applies degree units, the saved relative target cap (currently 5), hold-on-disconnect, five-second camera warmup, and bounded H.264 encoding. Existing motor calibration is checked instead of rewritten on connection. No physical robot session was started during this integration.

Verification:

- All 21 existing project tests pass in the original environment.
- All five new integration tests pass in the LeLab environment.
- Native LeLab record/reset/redo handlers, with fake hardware and real dataset/video writing, discard the first take and save two six-frame episodes. Both camera videos decode 12 frames; reset phases receive no dataset and both devices connect once across the loop.
- Generated recording and teleoperation configs preserve the saved cap, units, calibration selection, warmup, and encoder settings. Calibration mismatches fail without register writes; the device factories are tested without opening serial ports.
- UI loads, lists SO101 as Ready, and opens the recording configuration with both 640×480/30 fps cameras. The form was prepared for five episodes with 30-second recording/reset intervals. Start Recording was not pressed.

The browser preview has no browser-device binding in the seeded profile; the backend capture indices are configured. Real camera capture and motor behavior in this LeLab runtime still require the operator's first test. The earlier intermittent wrist-camera failure is not declared solved. This is software readiness, not completion of C3 or a training-ready dataset.
